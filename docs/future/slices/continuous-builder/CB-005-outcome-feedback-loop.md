# CB-005 — Outcome Feedback Loop

**Status:** Designing

## Purpose
Make shipped work affect future decisions.

## Capture
Use, user satisfaction, time saved, revenue/value created, errors, reversals, ignored features, required corrections, and follow-up ideas.

## Rules
Do not infer success merely because a PR merged or tests passed. Product outcome is separate from software correctness.

## Acceptance
A completed slice can produce outcome evidence that updates future priority/recommendation inputs while preserving raw historical evidence.
