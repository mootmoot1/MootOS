# MootOS Future Constitution

These rules govern future planning and must be reconciled with current ADRs before implementation.

1. **Human final authority.** Main merge, high-risk spending, destructive production actions, credential/permission changes, and major architecture changes remain human-gated unless a later explicit ADR narrows that boundary.
2. **Truth before fluency.** Never claim an action happened until the authoritative system proves it.
3. **Registry truth.** Runtime capability truth comes from live registered/configured capability state, not roadmap prose.
4. **Modular providers.** External vendors and models are adapters.
5. **Least privilege.** Give each worker only the tools and scope needed for the mission.
6. **No silent architecture drift.** Major shared abstractions require a proposal/ADR.
7. **Quiet reuse, intentional invention.** Reusing existing shared components needs no interruption; inventing a new platform layer does.
8. **Evidence-based autonomy.** Oversight may relax only after measured reliability; high-risk areas remain strict.
9. **Main is sacred.** Staging autonomy does not imply Main autonomy.
10. **Rollback required.** Meaningful changes must state how they can be undone.
11. **Failures become assets.** Valid failures become regression tests and playbook lessons.
12. **No blind lab promotion.** Evolution Lab code never enters production merely because it works in the lab; production architecture reviews and gates still apply.
13. **Cost-aware, not cost-crippled.** Optimize waste, context, and routing without intentionally making important work worse to save trivial spend.
14. **Goal alignment.** Priority should favor work that improves Moot, improves MootOS, saves time, creates value, increases reliability, or unlocks future capability.
15. **Explain consequential decisions.** Important recommendations include evidence, alternatives, confidence, downside, and reversibility.
