# MootOS Version 0.1 Requirements

**Last reviewed:** August 1, 2026

## Purpose

Version 0.1 is the reliable single-user foundation for private chat, persistent memory, controlled memory lifecycle changes, and reviewable development.

## Production-verified

- Private Railway deployment
- One SQLite database and one Railway replica
- Persistent conversations and messages
- Five default projects
- Replaceable provider boundary with OpenAI implemented
- Explicit chat memory-save commands
- Atomic write-before-confirm behavior
- Cross-chat recall surviving rebuilds
- Protected Memory page
- Active memory filters by all, global, and exact project
- Manual off-volume backup and isolated restore drill
- Schema 2 memory lifecycle
- UI-selected correction with preserved history
- Superseded rows excluded from normal recall
- Corrected memory surviving a rebuild

## Current branch requirements — recoverable forget

The branch is complete only when all of these are true:

- One exact active memory can be archived after explicit confirmation.
- Archived rows disappear from active lists and model context.
- Archived memories have a separate protected view.
- One exact archived memory can be restored after confirmation.
- Restore returns the same row to active recall.
- Correction links survive archive and restore.
- Archived rows cannot be hard-deleted through the legacy API.
- Missing and wrong-state requests fail clearly.
- Concurrent requests cannot create contradictory lifecycle states.
- Forced database failures roll back.
- The browser safely renders stored content.
- The browser exposes no permanent-delete request.
- All new endpoints remain authenticated.
- Tests, ADR, API documentation, current implementation, and checkpoint documentation ship together.
- CI passes on Python 3.9, 3.10, and 3.11.
- External review finds no blocker.
- Moot explicitly approves the exact PR head before merge.
- Railway production verification is completed after merge.

## Explicitly not required in this branch

- Natural-language forget
- Secure erasure or permanent-delete UI
- Bulk archive/restore
- Automatic retention
- Keyword or semantic search
- Full browser history viewer
- Multi-user roles

## Remaining Version 0.1 work after forget

- Keyword retrieval before embeddings
- Duplicate and conflict handling
- Conversation behavior refinement
- Curated bootstrap profile
- Basic readable activity/settings surfaces
- Automatic encrypted backups and scheduled restore verification
- Version 0.1 release review

## Non-negotiable operating requirements

- One focused branch and PR at a time
- One Railway replica while SQLite is live
- No secrets or private database content in GitHub
- No silent long-term-memory writes from ordinary conversation
- No destructive lifecycle action without explicit selection and confirmation
- No merge without tests, review, and Moot’s exact approval
